# Threat model — PortPilot agents platform

Status: **first version 2026-11-01** (Engineering hygiene plan H2). Scope: what exists today — the data stores, the
retrieval tool, the agent graphs (`weekly_pack`, `finance_qa`, `route_advice`, `voyage_watch`, the supervisor), the
CLIs and the scheduled tasks, on one Windows machine; since 2026-11-04 the HTTP API on the loopback (FastAPI plan,
ADR-064; its table below). The web frontend (ADR-060) has its own table below.

Each row: the risk, the control that exists (with its decision record and the check that proves it), and the gap.
"Control" means it exists and is tested; "Gap" means it is planned, partial or missing.

## OWASP Top 10 for LLM Applications (2025)

| # | Risk | Control today | Gap |
|---|---|---|---|
| LLM01 | Prompt injection (direct, and indirect through documents, uploads, web results) | Project rule 5: retrieved text is data, never instructions; the `untrusted-content` skill in every agent that reads documents; uploads pass a validator + three-layer injection screening in EN / MSA / Egyptian Arabic (`pipelines/lib/screening.py`, ADR-042) and stay labelled `untrusted_upload` (ADR-043); web results are never evidence for a number (ADR-049); leakage 0 in `Views_eval.py`); **a third (2026-11-07, approver-request plan, ADR-067):** the manager's request in words reaches one structured call whose only output is the pack's own decision kinds or an ask-back (`ApproverRequest`, no free action); | LLM04 | Data and model poisoning | The corpus is ingested by reviewed scripts with reviewed snapshots (ADR-036); a manager's upload reaches the corpus only by promotion (ADR-044); golden sets are frozen with sha256 and change only by a recorded REFREEZE (ADR-053); models are hosted, not fine-tuned | The review queue (`nilegate-review`) feeds future golden items — each needs the owner's review before it enters a frozen set |
| LLM05 | Improper output handling | Model output is never executed and never written to a database; every number in a deck or answer is a slot filled by code from a tool result and read back (Validator v2 + V8, ADR-051; `check_answer` / `check_supervisor_answer`); a pack is published only after a human approval (ADR-050); PPTX text is written through python-pptx (no macros) | Closed 2026-11-08: the web renders model text as plain text only (no HTML, no Markdown, no images from model text), with a nonce CSP (ADR-060 amendment 3; `web/tests/security.e2e.spec.ts`) |

## OWASP Agentic AI — threats and mitigations (selected, those that apply to this platform)

| # | Threat | Control today | Gap |
|---|---|---|---|
| T1 | Memory poisoning | Agent memory = PostgresSaver checkpoints per thread, written only by the graphs; no long-term memory shared across users; retention archives then deletes ended threads (ADR-054). Conversation memory (ADR-065, `api.conversation_turns`): one employee's conversation only; the frame is built by code from the user's own words and the answer's cited rows — never document, upload or web text, never an entity of a refused part, never an earlier answer's number (stored masked); a model rewrite is accepted only if it names no entity outside the frame and adds no number; deleted when the conversation closes (`Memory_check.py`) | Long-term memory across conversations not built (DEFERRED, its own ADR if ever) |
| T2 | Tool misuse | Typed tool arguments (pydantic, ADR-049); the run context carries the user and the dataset, the model cannot choose them; refused tools never offered (ADR-059) | — |
| T3 | Privilege compromise | The user comes from the run context, checked in PostgreSQL; the scheduled identities (`PACK_RUN_AS`, `WATCH_RUN_AS`) must hold the right role; an approval is checked against the approver's role | The API: email + scrypt password → a hashed, revocable bearer token, 5 failures lock 15 min, the same 401 for unknown email and wrong password; the employee from the token at every request (`Api_check.py` Phase 1). The CLIs still trust `--as` (owner-run on the owner's machine) |
| T5 | Cascading hallucination | Each graph validates its own output in code before anything leaves it; the supervisor checks the product tools' rows, not their prose | — |
| T8 | Repudiation and untraceability | One `agent_state` thread + one LangSmith trace per run, linked by `thread_id`, also tagged in Sentry (ADR-062); the approval log outlives the thread (archive) | `api.audit_log` built (migration 023); the request id links the access log, the audit row, Sentry and LangSmith |
| T10 | Overwhelming the human in the loop | One pending pack at a time; a degraded pack is marked for the approver (c4); a toast only when a pack waits or a high alert exists | — |
| T11 | Unexpected code execution | No code-execution tool; uploads: active PDF / DOCX content rejected, DOCX XML parsed with defusedxml (ADR-042) | — |

## Web API (OWASP API Security Top 10, 2023) — the FastAPI layer (ADR-064)

| # | Risk | Control | Proof |
|---|---|---|---|
| API1 | Object-level authorization (IDOR) | every thread / run / conversation / upload checked against the caller (owner, or the CEO for reading); another employee → 404, the same as "does not exist" | `Api_check.py` Phases 5–8 (route and arrival advice included); the local-stack E2E (`web/tests/stack/`) |
| API2 | Broken authentication | scrypt (N 2^17) passwords, 256-bit tokens stored as SHA-256 only, 8 h expiry, revocation, lockout, a dummy hash for unknown emails (same body, same time) | Phase 1, `check_api_user.py` |
| API3 | Object property level authorization | request models forbid unknown fields (no employee id, role or dataset from a client); responses are explicit models, never state dumps; events carry names only | Phases 3, 4, 8 |
| API4 | Unrestricted resource consumption | body 16 KB (uploads 5 MB), question 2,000 chars, run slots + queue, per-employee limits, time limits, the shared daily quota | Phases 3, 5; `Load_test.py` |
| API5 | Function-level authorization | pack decisions: the graph's approver rule checked here and again in the graph; promotion: a manager, own department; pack reads: the finance views' RBAC | Phases 6, 7 |
| API7 | SSRF | the API takes no URL from a client; outbound hosts are the tools' fixed ones; upload links never fetched | by design (ADR-042) |
| API8 | Security misconfiguration | loopback bind, one process; `nosniff`, `Content-Security-Policy` (JSON: `default-src 'none'`), `X-Frame-Options`, `no-referrer`, `no-store`; CORS for the UI origin only, no credentials, `*` refused; problem+json errors without stack, SQL, path, key or the client's input | Phase 9 |
| API9 | Improper inventory | one versioned base path; the OpenAPI schema committed (`docs/api/openapi.json`) and diffed in the CI (`tools/openapi_snapshot.py --check`) | CI |
| API10 | Unsafe consumption of APIs | external results cached, screened for injection, never evidence for a number (ADR-049); uploads labelled `untrusted_upload` | injection set v3 |
| — | XSS | the API returns JSON only, model text as strings; the UI renders text / sanitized Markdown (ADR-060 (3)) | headers in Phase 9 |
| — | CSRF | the API itself takes bearer tokens in a header (no cookies); the web's cookie session is protected at the BFF (Web UI table below) | by design |
| — | Logs | the access log holds route templates, statuses, times, employee and request ids — never a token, password, question or body | Phase 9 |

## Web UI (the Next.js BFF and pages, ADR-060 amendment 3)

| Threat | Control | Proof |
|---|---|---|
| XSS through model text (answers, bullets, alerts, reasons) | rendered as plain text only — never `dangerouslySetInnerHTML` (ESLint `react/no-danger`), no Markdown renderer (D-FE-8), numbers as chips from the API's spans; CSP `script-src 'self' 'nonce-…' 'strict-dynamic'`, `object-src 'none'`, `base-uri 'none'` | `security.e2e.spec.ts`: `<script>`, `<img onerror>`, a `javascript:` link, a Markdown image and an outside link in an answer render as characters — no element, no script run, no dialog, no request out |
| Session token theft | the API token lives only in the httpOnly, `SameSite=Strict`, `Secure` cookie `ng_session`, set by the BFF; the browser gets `me` only; nothing in `localStorage` / `sessionStorage`; a 401 from the API clears both cookies; sign-out revokes the token at the API | `auth.e2e.spec.ts` (cookie flags, `document.cookie`, storage, a revoked token → 401) |
| CSRF | three layers: SameSite=Strict, the Origin (or `Sec-Fetch-Site`) must be the app's own (`NILEGATE_WEB_ORIGIN`), a double-submit token compared in constant time on every unsafe method; sign-in checks the Origin | `bff.e2e.spec.ts` (403 cross-origin / without the token) |
| Open proxy / SSRF through the BFF | one fixed upstream from the environment (never from the request); only the (method, path) pairs of the committed OpenAPI schema; path segments by pattern (no `.`, `..`, `/`); header allow-lists both ways (no cookie upstream, no `Location` / `Set-Cookie` back); body limits = the API's | `bff.e2e.spec.ts` (404 outside the schema, 405), `auth.e2e.spec.ts` (no cookie header upstream) |
| Clickjacking | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` on every page | `security.e2e.spec.ts` (every page) |
| Exfiltration through images / links in model text | no `img` / `a` from model text; CSP `img-src 'self' data: blob:`, `connect-src 'self'`; `Referrer-Policy: no-referrer` | `security.e2e.spec.ts` (no request leaves the origin) |
| Access decided in the browser | the menu from `/me` is a comfort only; every page's data comes from the API, which refuses (403 / 404 / `not_permitted`); another employee's thread → 404 | the local-stack E2E on the real API (`web/tests/stack/access.stack.spec.ts`: seven profiles, pages + BFF reads, another employee's conversation / answer refused, the CEO reads by design — leakage 0, 2026-11-16); the refusal tests of `routes` / `voyages` / `packs` / `finance` specs; the real-API smoke (an operations employee gets no figures) |
| Dependency supply chain (npm) | exact pins at least two weeks old (`npm_config_before`), `.npmrc` `save-exact` / `engine-strict`, npm 11 runs no unapproved install script, `npm audit --omit=dev` high = 0 in `npm run check` and the CI, Dependabot `npm` for `/web`; shadcn's `cn` package removed (unreviewed). **One time-limited exception (owner, 2026-11-18):** GHSA-fc5q-39xc-vjpf, picomatch ≤ 4.0.7, no patched release; the attack needs a glob pattern chosen by the attacker, and `web/src` neither imports picomatch nor builds a glob from input. `web/scripts/audit-gate.mjs` ends it on 2026-12-18 or at the next picomatch release, and every other high / critical advisory still fails | `npm run check`, `tests/audit-gate.logic.spec.ts` |
| Container | `compose.yaml` publishes on 127.0.0.1 only; user `node`, read-only root filesystem, all capabilities dropped, `no-new-privileges`; `.env*` never in the build context (`.dockerignore`) | `docker compose up -d web` + the real-API smoke against it (2026-11-08) |

Accepted: `style-src 'unsafe-inline'` (Recharts / Radix / React Flow style attributes; scripts stay nonce-only).

## Public deployment (staging / production on a VM, ADR-071, 2026-11-17)

| Threat | Control | Proof |
|---|---|---|
| Eavesdropping, downgrade | Caddy terminates TLS (Let's Encrypt), HSTS one year, plain http only redirects; cookies `Secure`, `SameSite=Strict`, httpOnly | `Deploy_smoke.py` (HSTS, redirect) |
| Direct access to the API or a store | only the proxy publishes ports; `/api/*`, `/docs`, `/openapi.json` answer 404 at the proxy; the API, PostgreSQL, MongoDB on internal networks; Qdrant on the host loopback with its API key; the NSG opens 80 / 443 only (SSH from the owner's address, or none) | `Deploy_check.py` Phase 2; `Deploy_smoke.py` (404s) |
| CSRF / origin confusion on the real domain | `PORTPILOT_WEB_ORIGIN` = the exact public origin; the API's CORS refuses a non-https origin outside local | `Deploy_check.py` Phase 1; `bff.e2e.spec.ts` |
| Password guessing | per login: 5 failures → 15 min lock (API); per client address behind the proxy: 10 failed sign-ins / 10 min → 429 (BFF, the proxy's own X-Forwarded-For entry); passwords ≥ 12 characters | `signin-limit.logic.spec.ts`; `Api_check.py` Phase 1 |
| Oversized bodies | 6 MB at the proxy, then the BFF / API limits (16 KB JSON, 5 MB uploads) | `Deploy_check.py` Phase 2 |
| Test modes in a real environment | `--fake-roles` / `API_FAKE_ROLES` and the fake app refused when `PORTPILOT_ENV` ≠ local; inherited logins disabled and tokens revoked by `Backup.py secure` | `Deploy_check.py` Phase 1; the CI `images` job |
| Secrets in images, git or logs | no `.env` in any image (dockerignore), each container lists only its variables (the owner's DB password in `postgres` / `ops` only), Key Vault + managed identity on the VM, fresh credentials per environment; `tools/secrets_scan.py` in the CI + `gitleaks dir` (0 on 2026-11-17); Caddy redacts cookies / authorization in its logs | `Deploy_check.py` Phases 2, 3, 6; CI |
| Container escape / tampering | non-root users, read-only roots, all capabilities dropped (`NET_BIND_SERVICE` for Caddy only), `no-new-privileges` | `Deploy_check.py` Phase 2; CI `images` |
| Data loss | nightly backups with hashes, 7 + 4 kept, off-host blob copy; restore compares every count and digest | the drill of 2026-11-17 (plan §8) |
| Unreviewed deploys | manual workflow, the owner as required reviewer, a second approval to apply migrations, CI green required, OIDC (no stored cloud secret) | `.github/workflows/deploy.yml` |

Gaps: one VM is a single point of failure (recovery = the restore runbook); the sign-in limit is per process and
forgets on restart (the API's lockout is the durable layer); the git history still holds the pre-ADR-015 local
password until the owner rotates it (runbook §10–11).
